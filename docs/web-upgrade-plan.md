# 数字人互动体验开发方案

目标：基于官方新版 Agent SDK，把现有表演控制台升级为普通人能直接参与的桌面 Web 互动页。先让聊天和情景对练跑通，保持原生前端与轻量 Node 服务。

## 1. 首版做什么

### 聊聊今天

提供「安慰我」「陪我吐槽」「给点建议」三个入口，每个入口有两到三条示例话题。用户点示例或输入自己的内容，数字人接话；既能打字，也能点击麦克风说话。

默认引导回答简短、一次只追问一个问题，避免数字人长篇独白。这里的语气和场景用普通会话开场指令实现；若要稳定人设，再使用平台或模型服务支持的配置。

### 陪我练练

首版内置三个场景：

| 场景 | 用户体验 |
| --- | --- |
| 模拟面试 | 数字人问三个问题，用户逐一回答，再点击生成点评 |
| 练习提涨薪 | 数字人扮演主管，围绕理由、成果和诉求进行三轮练习 |
| 自我介绍 | 从介绍自己开始，再练重点表达与补充说明 |

页面展示「第 1 / 3 轮」、当前目标和一个表达提示。第三轮回答完成后显示「生成点评」，由用户点击，让数字人总结一个亮点和一个建议。

不要求模型自动输出严格评分格式。点评直接显示在对话记录中，同时由数字人播报。

### 更多玩法

保留现有的自定义播报、打招呼、跳舞、音量和主题切换。收进次级区域，让主要页面围绕聊天和练习展开。

新版全部使用一个 Agent SDK 实例。旧模拟流式和自动演示不作为首版主功能，不再为它们维护另一套 SDK 接入。

## 2. 桌面页面

只设计桌面 Web，按 1280、1440、1920px 宽度检查，不做手机布局。

- 顶部：项目名称、连接状态、凭证设置、主题切换。
- 左侧约 45%：数字人舞台、字幕、当前状态，以及明显的「打断一下」按钮。
- 右侧约 55%：聊天 / 对练切换、话题或场景选择、当前提示卡、对话记录、固定在区域底部的文字和麦克风输入。
- 对练结束：显示「生成点评」「再练一次」「换个场景」。

首次没有凭证时展示玩法说明与「配置后开始」。只有实际初始化以后才显示下载进度。日志和积分查询收进设置，不占主要交互空间。

首版用现有数字人截图或静态封面即可，不把新拍录屏作为开发前置条件。

## 3. 使用哪些官方能力

固定 SDK 文件：

`https://media.xingyun3d.com/xingyun3d/general/litesdk/xmovAvatar_e2e.2.4.1.js`

默认网关：

`https://nebula-agent.xingyun3d.com/user/v1/ttsa_v2/session`

| 功能 | 接法 |
| --- | --- |
| 文字对话 | `agent.ask(text)`，回复和播报由 Agent 链路处理 |
| 语音输入 | `startASR()` 开始收音，`stopASR()` 结束监听 |
| 识别文字 | `onASRResult` 更新临时文字与最终用户消息 |
| AI 回复 | `onLLMResponse` 更新当前回答，最终文本回填完整内容 |
| 本轮说完 | 用 `speak_end` 或官方明确的对话完成事件恢复输入 |
| 手动打断 | `interrupt()` 停止当前播报；若正在监听，再单独停止 ASR |
| 内容联动 | 场景开场的固定 `speak()` 中使用 `<uievent>`，前端接收后展示文字提示卡 |

ASR 最终识别会自动进入 Brain 链路，前端不要在该回调里再调用 `ask()`。`ask()` 返回、LLM 生成结束、声音播放结束是不同节点：恢复输入按实际整轮播放完成处理。

「结束监听」只负责关闭当前麦克风采集，不把它当作保证提交最终识别结果的发送按钮；页面以 ASR 最终结果回调为准。首版需要实际验证目标应用的识别断句与自动送问效果。

打断按钮按「停止当前播报」验收，不宣称它取消了模型生成。首版不做自动检测用户抢话。

### 平台配置前提

准备一个可用于新版 Agent 的应用，并配置可用的 Brain、ASR 和 TTS。默认沿用平台配置，不新增自建模型网关。

先用这个应用跑通一句文字问答和一次语音问答，再开发场景。这样能尽早确认账号配置是否满足首版需求。

## 4. 场景怎样实现

新增 `scenes.js`，用普通对象保存配置：

- 场景 ID、标题和简介。
- 发给 Agent 的开场指令。
- 开场目标卡内容。
- 三轮练习的提示文字。
- 点评指令。

开场指令示例：

> 现在开始一段求职面试练习。请扮演友善的面试官，围绕我的经历提问，每次只问一个简短问题。我回答后继续追问。先请我介绍自己；我要求点评时，再给一个亮点和一个改进建议。

这是一条普通用户指令，不虚构 `systemPrompt` 接口，也不把它当强制执行规则。轮次数由页面按用户实际回答计数，开场指令与点评请求不计入三轮。

流程：

1. 选择场景并开始；显示该场景目标卡。
2. 用固定开场播报加 Widget 事件展示提示卡。
3. 开场播报完成后，通过 `ask()` 提交场景设定，让数字人提出第一个问题。
4. 用户打字或说话回答；每个最终回答只记录一次，轮次加一。
5. 数字人回答播放完成后恢复输入。
6. 第三轮结束后突出「生成点评」；点击后发送点评指令。
7. 点评播完，显示「再练一次」「换个场景」。

模型偶尔偏离三问节奏时，页面仍提供「生成点评」，不为此增加解析器、工具调用或严格 JSON 协议。

切换场景或点击「再练一次」时，停止监听、打断播报，销毁当前实例，再创建一个新实例。直接复用同一初始化函数，避免把清空页面记录误当成清空服务端对话历史；不让两个实例同时运行。

Widget 只先接一种 `show_text` 事件。后续轮次的提示可以直接按前端配置更新，不要求模型生成特殊事件。图片、视频和复杂剧情分支后做。

## 5. 文件改动

| 文件 | 工作内容 |
| --- | --- |
| `public/index.html` | 更换 SDK 引用，改成桌面舞台 + 对话区，增加场景入口、麦克风和打断按钮 |
| `public/style.css` | 沿用现有主题，调整桌面双栏、消息样式、提示卡和输入区 |
| `public/sdk-agent.js`（新增） | 管理唯一 Agent 实例；提供初始化、提问、收音、停止播报、销毁；转发需要的回调 |
| `public/scenes.js`（新增） | 保存聊天语气、三个练习场景、提示和点评指令 |
| `public/main.js` | 继续管理 DOM、配置弹窗、对话记录、场景选择、轮次和按钮状态 |
| `server.js` | 改默认网关，沿用现有配置与静态服务 |
| `.env.example` | 更新新版网关与平台服务配置说明 |
| `.github/workflows/ci.yml` | 修复预期 HTTP 400 的检查，让现有 CI 能正确通过 |
| `README.md` | 更新运行步骤、玩法、新 SDK 版本与配置前提 |

现有 `.env` 中如果写了旧网关，运行新版前同步改为新版地址；页面的默认网关和凭证表单占位符一起更新。

继续使用普通 `<script>`，不新增构建工具。加载顺序为：SDK、场景配置、SDK 接入文件、`main.js`。

## 6. 代码保持简单

页面只保留必要状态：当前模式、场景、轮次、是否可交互、是否正在监听、是否等待回答或播报。

- 一次只处理一轮对话，等待期间禁用重复提交，保留打断按钮。
- `main.js` 直接操作 DOM，不引入全局状态库。
- SDK 文件只是薄封装，不写通用 provider 系统、插件体系或多层控制器。
- 对话记录保存在本次页面内存中；需要留存时复制文本即可。
- 初始化、提问和麦克风失败时，显示简短原因和「重新开始」。不做自动重试链路。
- API 返回的文本按普通文本渲染。

## 7. 开发顺序

### 第一步：新版 SDK 正常接通

换固定脚本、构造器和网关；用现有凭证配置流程初始化。完成文字问答、回复显示和数字人播报。

完成标准：输入一句话，数字人能回答；回答结束后可以继续问。

### 第二步：语音和打断

接入麦克风、识别文字、最终用户消息和显式打断。

完成标准：一次语音只产生一次回复；能停止当前播报并继续进行下一次交互。

### 第三步：聊天与三轮对练

加入语气入口、三个练习模板、轮次、点评和重新开始；接一个文字 Widget 提示卡。

完成标准：能完整完成一场练习，得到口头点评，再开始另一场。

### 第四步：桌面页面与发布收尾

整理双栏布局，收起旧控制项，调整首次配置引导，修 CI，更新 README 和演示截图。

完成标准：从仓库启动到完成一次体验，按 README 可以走通。

平台配置就绪的前提下，可按 4–6 个开发日安排；具体以第一步的真实接通结果调整。

## 8. 首版验收

1. 本地 `npm start` 能启动，固定 SDK 和新版网关可用。
2. 三种聊天入口能正常文字问答，并显示用户和数字人的记录。
3. 语音最终识别自动触发一次回答，允许用户结束监听。
4. 三个练习场景都能完成三轮并点击生成点评；再练一次可重新开始。
5. 播报中可以显式打断；开场能展示一张 Widget 文字卡；桌面布局在目标宽度下可正常操作。

用真实应用手动走完这些主流程即可。语法检查和现有启动冒烟保留，不为这次升级建立大型测试体系。

2026-10-29 实现验证记录：

- 本地执行 CI 的全部三个步骤通过，包括脚本语法、无凭证与假凭证启动、静态资源和预期 HTTP 400。
- 浏览器使用模拟 Agent 驱动实际页面，验证三种聊天入口、三个场景的三轮与点评、ASR 不重复提问、打断与重开、实例销毁、复制记录、自定义播报和 KA 动作调用。
- 检查了 1280×800、1440×900、1920×1080 的桌面布局、亮暗主题，以及设置弹窗的键盘退出。
- 在本地模拟 `/xingyun3D/` 静态部署路径，验证资源加载、缺少 `/api/config` 时回退至站点配置、旧默认网关迁移和静态模式禁用积分查询。
- 使用本地应用请求真实新版网关，平台返回「您的积分不足」。真实数字人播放、Brain 回答和麦克风识别尚待额度可用后完成验收；模拟联调不代表这些云端能力已通过。

## 9. 本轮暂缓

手机与平板适配、登录和数据库、历史会话管理、长久记忆、自动语音抢话、多角色同台、复杂剧情引擎、模型自动故障切换、录屏导出、云端分享、性能统计面板。

祝福玩法已在首版模拟联调基础上追加，见下方后续开发记录；真实云端验收仍按第 8 节的额度前提执行。

### 2026-10-29 后续开发：送句祝福

- 新增「送句祝福」模式，包含生日祝福、节日问候、加油鼓励三个模板，配置继续保存在 `scenes.js`。
- 复用现有输入、麦克风、提示卡与 Agent 对话；每次连接先建立模板语境，用户说出对象和心意后生成祝福，也可以继续提出修改要求。
- 支持复制最近一份完整祝福、按原文再次播报、重新建立会话写一份新祝福。再次播报使用转义后的固定文本，不再请求模型，不重复插入消息。
- 完整正文返回后，即使停止播报或播报失败，也保留复制、重播能力；不把未完成的生成片段覆盖到上一份完整祝福。
- 连接引导完成后保留示例入口；结果操作区出现后滚动到最新消息。切换模式、模板或重新开始会清空本次记录并重建唯一实例。
- 本地通过脚本语法、无凭证与假凭证启动、静态资源及预期 HTTP 400 检查；以上检查没有向云端发起会话请求。
- 浏览器使用模拟 Agent 验证三个模板、文字修改、ASR 最终结果去重、复制正文、原文重播、SSML 转义、打断、播报失败、连接失败重开与旧实例回调隔离，并回归三轮对练和点评。
- 检查 1280×800、1440×900、1920×1080 桌面布局、亮暗主题及减少动态效果偏好。真实 Brain 文案质量、语音识别和数字人播报仍待额度恢复后验收。
- 独立复核发现同一实例打断后的迟到回调会串入下一轮：打断后现在先锁定输入、销毁并静默重建实例；记录、轮次和完整祝福保留，下次用户输入时才携带恢复语境，不额外请求或播报恢复话术。重建会增加一次连接；恢复后的 ASR 会话关闭 SDK 自动送问，由前端只提交一次最终结果。
- 麦克风启动使用 attempt 标识隔离旧 Promise 的拒绝；结束监听后锁住下一次输入并等待最终识别，10 秒未收到时重建连接，避免上一段录音的迟到结果终止下一段。异步 `ask()` 的失败也检查所属实例与轮次。
- 场景设定失败会回滚开始状态并显示重试入口。已用延迟的旧 `ask()`、麦克风启动拒绝、旧实例 LLM/播报回调和练习中断恢复进行确定性回放。
- 祝福只在 LLM `done` 时提交完整结果，允许 `done` 不带正文并使用累计分块；仅 `speak_end` 不会把半截文本标成完整。生成式轮次等待 LLM 完成和播报完成两个节点都到达后才开放输入。

### 2026-10-29 界面升级：对话工作室

- 页面改为左侧玩法导航、中间数字人舞台、右侧对话工作台；使用暖白、炭黑和浅紫色，重新设计标题层级、场景卡、消息、输入框、设置弹窗与亮暗主题。
- 未连接时，舞台将人物预览与欢迎文案并列展示，以柔和边缘、聚光和轨道装饰衔接原始图片。连接后保留真实 SDK 容器，预览不会冒充实际数字人播放。
- 小桌面压缩场景卡和提示的重复说明，保留完整示例入口与固定输入区；产生消息后自动收起场景说明，给对话记录留出空间。
- 补齐四个交互边界：文本发送失败恢复用户草稿和练习轮次；首问设定中断恢复练习入口；仅 Agent `running` 状态开放交互；初始化期间禁用凭证保存与清除，并在事件处理函数中再次校验。
- 在实际浏览器中用模拟 Agent 验证上述边界，并回归语音最终结果去重、祝福生成/复制/原文重播、三个练习场景的三轮及点评。始终只有一个未销毁实例，未发起真实云会话。
- 检查 1280×800、1440×900、1920×1080 布局，亮暗主题、减少动态效果、设置弹窗 Escape 退出与焦点返回；主要文字在两种主题下对比度均不低于 4.5:1。脚本语法、本地无凭证/假凭证启动、静态资源及预期 HTTP 400 检查通过。
